# Техническое задание

**на разработку функционала цветового кодирования направления сигнала в виджете водопада программного комплекса изделия «Сириус»**

## 1. Общие сведения

**Наименование функционала:**
Подсистема цветового отображения направления сигнала в виджете водопада.

**Объект разработки:**
Виджет спектрально-временного отображения сигналов типа «водопад» в программном комплексе изделия «Сириус».

**Основание для разработки:**
Необходимость повышения информативности визуализации радиосигналов и упрощения интерпретации оператором направления прихода сигнала без перегрузки интерфейса. В документах по проекту водопад определён как основной инструмент визуализации сигналов, а синхронизация визуализации с пеленгованием выделена как отдельная задача .

---

## 2. Назначение разработки

Разрабатываемый функционал предназначен для отображения в виджете водопада не только амплитуды сигнала, но и **относительного направления его прихода** по двум лучам/каналам антенны с помощью цветового оттенка.

Функционал должен позволять оператору:

* визуально оценивать наличие и интенсивность сигнала;
* видеть, в каком луче сигнал выражен сильнее;
* быстрее ориентировать антенну в сторону источника сигнала;
* сократить необходимость постоянного переключения внимания между водопадом и отдельным индикатором направления.

---

## 3. Цель разработки

Целью разработки является внедрение в виджет водопада механизма, при котором:

* **яркость пикселя** отображает амплитуду сигнала;
* **цветовой оттенок пикселя** отображает направление сигнала относительно двух лучей антенны.

---

## 4. Область применения

Функционал применяется в составе программного комплекса изделия «Сириус» в режиме визуализации и анализа сигналов в реальном времени.

---

## 5. Термины и обозначения

В настоящем ТЗ используются следующие обозначения:

* `A_L` — амплитуда сигнала в левом луче;
* `A_R` — амплитуда сигнала в правом луче;
* `A` — результирующая амплитуда для отображения яркости;
* `B` — нормированная яркость пикселя;
* `D_raw` — исходный нормированный показатель направления;
* `D` — показатель направления после применения мёртвой зоны;
* `K` — коэффициент смешивания directional-цвета;
* `C_base` — базовый цвет пикселя по амплитуде;
* `C_left` — эталонный цвет левого направления;
* `C_right` — эталонный цвет правого направления;
* `C` — итоговый цвет пикселя водопада.

---

## 6. Исходные предположения

1. На водопад подаются данные уже после аппаратной фильтрации, настраиваемой через БЦО, поэтому отображаемый сигнал является очищенным от основного шума.
2. Для каждого отображаемого элемента водопада доступны амплитудные значения по двум лучам/каналам: левому и правому.
3. Текущий виджет водопада уже реализует базовое построение строк по времени и частоте.
4. Новый функционал должен быть встроен без нарушения существующей логики отображения.

---

## 7. Функциональные требования

### 7.1. Общие требования

Функционал должен обеспечивать:

* расчёт цвета каждого пикселя (или ячейки) водопада на основе двух входных амплитуд;
* разделение визуальных признаков:

  * амплитуда — через яркость;
  * направление — через оттенок;
* работу в реальном времени;
* возможность включения и отключения directional-режима;
* возможность настройки параметров цветового кодирования.

### 7.2. Режимы работы

Должны поддерживаться следующие режимы:

1. **Стандартный режим водопада**
   Цвет зависит только от амплитуды.

2. **Directional-режим водопада**
   Цвет зависит от амплитуды и от соотношения сигналов по левому и правому лучу.

### 7.3. Правила отображения

В directional-режиме должны соблюдаться правила:

* чем выше амплитуда сигнала, тем выше яркость;
* если сигнал сильнее в левом луче, оттенок должен смещаться в сторону цвета левого луча;
* если сигнал сильнее в правом луче, оттенок должен смещаться в сторону цвета правого луча;
* если амплитуды в левом и правом лучах близки, цвет должен быть нейтральным.

---

## 8. Требования к алгоритму расчёта цвета

### 8.1. Расчёт результирующей амплитуды

Для расчёта яркости должна использоваться формула:

```text
A = max(A_L, A_R)
```

Допускается возможность дальнейшего переключения на альтернативную формулу:

```text
A = (A_L + A_R) / 2
```

но базовой для реализации считается формула через максимум.

### 8.2. Нормализация яркости

Яркость должна рассчитываться по формуле:

```text
B = clamp((A - A_min) / (A_max - A_min), 0, 1)
```

где:

* `A_min` — минимальная отображаемая амплитуда;
* `A_max` — амплитуда насыщения шкалы.

Для улучшения визуального восприятия допускается применение гамма-коррекции:

```text
B_vis = B ^ γ
```

где `γ` — коэффициент гаммы.

### 8.3. Расчёт направления

Показатель направления должен рассчитываться по формуле:

```text
D_raw = (A_R - A_L) / (A_R + A_L + ε)
```

где:

* `ε` — малая положительная константа для защиты от деления на ноль.

Смысл:

* `D_raw = -1` — сигнал выражен только в левом луче;
* `D_raw = 0` — сигнал одинаков в обоих лучах;
* `D_raw = +1` — сигнал выражен только в правом луче.

### 8.4. Мёртвая зона

Для исключения ложного цветового смещения при близких амплитудах должна быть реализована мёртвая зона:

```text
if |D_raw| < D_dead:
    D = 0
else:
    D = sign(D_raw) * (|D_raw| - D_dead) / (1 - D_dead)
```

где `D_dead` — порог неопределённости направления.

### 8.5. Базовый цвет

Базовый цвет должен формироваться по яркости сигнала.
Для первой реализации допускается использование нейтральной серой базы:

```text
C_base = (B_vis, B_vis, B_vis)
```

### 8.6. Эталонные directional-цвета

Для directional-подсветки должны использоваться два эталонных цвета:

```text
C_left  = (1.0, 0.35, 0.35)
C_right = (0.35, 1.0, 0.35)
```

Допускается последующая настройка цветовой палитры через параметры интерфейса.

### 8.7. Коэффициент смешивания

Сила directional-оттенка должна рассчитываться по формуле:

```text
K = α * |D|
```

где `α` — максимальная интенсивность directional-подмешивания.

### 8.8. Итоговый цвет

Итоговый цвет пикселя должен рассчитываться следующим образом:

если `D < 0`:

```text
C = (1 - K) * C_base + K * C_left
```

если `D > 0`:

```text
C = (1 - K) * C_base + K * C_right
```

если `D = 0`:

```text
C = C_base
```

## 9. Требования к пользовательскому интерфейсу

### 9.1. Элементы управления

В интерфейсе виджета водопада должны быть предусмотрены:

* переключатель:

  * «Обычный водопад»
  * «Водопад с отображением направления»
* настройка чувствительности directional-окраски;
* настройка порога мёртвой зоны;
* настройка яркости/контраста;
* настройка палитры направления;
* кнопка возврата к значениям по умолчанию.

### 9.2. Подсказки оператору

Должны быть предусмотрены:

* легенда цветовой шкалы;
* подписи:

  * «левый луч»
  * «равно»
  * «правый луч»
* пояснение:

  * яркость соответствует силе сигнала;
  * оттенок соответствует направлению сигнала.

### 9.3. Требования к читаемости

Интерфейс не должен:

* перегружать оператора избыточной цветовой информацией;
* ухудшать визуальное распознавание спектрально-временной структуры сигнала;
* мешать восприятию водопада как основного аналитического инструмента.

## 10. Нефункциональные требования

### 10.1. Производительность

Функционал должен обеспечивать расчёт цвета и обновление водопада в режиме, близком к реальному времени, без визуально заметных задержек. Это соответствует общим требованиям к программному комплексу изделия «Сириус» по непрерывному приёму, обработке и отображению данных .

### 10.2. Надёжность

Функционал не должен приводить к:

* зависанию интерфейса;
* нарушению отрисовки водопада;
* искажению уже существующих функций анализа.

### 10.3. Масштабируемость

Архитектура реализации должна допускать дальнейшее расширение:

* на большее число лучей;
* на другие цветовые схемы;
* на наложение дополнительной информации поверх водопада.

### 10.4. Модульность

Логика расчёта цвета должна быть вынесена в отдельный программный модуль/класс, чтобы не смешивать:

* получение данных,
* анализ амплитуд,
* алгоритм смешивания цвета,
* отрисовку интерфейса.

Это соответствует модульному принципу построения комплекса, указанному в материалах по проекту .

## 11. Входные данные

Функционал должен принимать на вход для каждой точки отображения:

* амплитуду сигнала по левому лучу;
* амплитуду сигнала по правому лучу;
* параметры нормализации яркости;
* параметры directional-режима.

Формат входных данных должен быть совместим с текущим внутренним представлением данных водопада.

## 12. Выходные данные

* визуально обновлённое изображение водопада;
* корректное отображение легенды и параметров directional-режима.

## 13. Параметры по умолчанию

Для первой реализации рекомендуется использовать значения:

```text
A_min   = минимальная отображаемая амплитуда, задаётся по текущей шкале водопада
A_max   = максимальная амплитуда насыщения, задаётся по текущей шкале водопада
γ       = 0.7
D_dead  = 0.1
α       = 0.35
ε       = 1e-9
```

Эти значения должны быть доступны для последующей калибровки.

## 14. Требования к тестированию

### 14.1. Функциональные тесты

Необходимо проверить следующие сценарии:

1. `A_L = A_R`
   Ожидается нейтральный цвет без directional-смещения.

2. `A_L > A_R`
   Ожидается смещение цвета в сторону левого оттенка.

3. `A_R > A_L`
   Ожидается смещение цвета в сторону правого оттенка.

4. `A_L > 0, A_R = 0`
   Ожидается яркий пиксель с максимально выраженным левым оттенком.

5. `A_R > 0, A_L = 0`
   Ожидается яркий пиксель с максимально выраженным правым оттенком.

6. Низкая амплитуда сигнала
   Ожидается тёмный цвет вне зависимости от направления.

7. Значения в пределах мёртвой зоны
   Ожидается нейтральный оттенок.

### 14.2. Визуальные тесты

Необходимо убедиться, что:

* водопад остаётся читаемым;
* слабые и сильные сигналы различимы по яркости;
* направление понятно по оттенку;
* интерфейс не выглядит перегруженным.

### 14.3. Нагрузочные тесты

Нужно проверить:

* устойчивость отрисовки при длительной работе;
* отсутствие деградации интерфейса при непрерывном обновлении;
* отсутствие заметной просадки производительности.

## 15. Критерии приёмки

Функционал считается реализованным, если:

1. В виджете водопада добавлен отдельный directional-режим.
2. Цвет каждого пикселя корректно рассчитывается на основе двух амплитудных каналов.
3. Яркость отражает интенсивность сигнала.
4. Оттенок отражает преобладающий луч.
5. Реализована мёртвая зона для подавления неопределённых направлений.
6. Реализованы настройки основных параметров отображения.
7. Производительность интерфейса соответствует режиму работы в реальном времени.
8. Функционал не нарушает существующую работу водопада и других элементов визуализации.

### Этап 4. Тестирование и настройка
